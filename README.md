# LongPath

**Длинные пути, которые мешают старым программам.** Выберите папку: самые длинные пути будут сверху.

Автор: **darkshade** ([@vlx0](https://github.com/vlx0)). MIT.

**365 дней open source · неделя 12 — «Файлы» · день 83.**

- Файлы и папки с длиной полного пути от выбранного порога (260 по умолчанию).
- Длина в кодовых единицах UTF-16: emoji может занимать две единицы.
- 260 — риск совместимости с классическими Win32-программами, не гарантия ошибки. Поддержка длинных путей зависит от приложения и Windows.
- Сам сканер использует расширенные пути Windows, чтобы читать деревья длиннее 260.
- Ссылки, junction и прочие reparse points пропускаются. Корень в результат не включается.
- Исключения по именам папок: `.git;node_modules;.venv` по умолчанию; пустое поле отключает исключения.
- Фильтр по пути, копирование, открытие папки, сохранение видимых результатов в UTF-8 TXT.
- Счётчики пропусков и ошибок, остановка с частичными результатами. При ошибках обход неполный.
- Чтение в фоновом потоке, без переименования и удаления.

## Запуск

Windows 10+, Python 3.10+ с tkinter, без pip.

```powershell
pythonw -m longpath
```

Или `start.bat` / `run_longpath.pyw`.

Настройки: `%APPDATA%\LongPath\settings.json`. Один экземпляр на сеанс Windows (mutex).
Открытие очень длинной папки зависит от поддержки Проводником; путь можно скопировать.
